GuardianAI - Final Year Project Architecture and Working Explanation
=================================================================

1. Project Overview
-------------------
GuardianAI is an AI-powered browser security extension and backend analysis system designed to detect phishing, malicious, or suspicious websites in real time. The project helps users identify risky domains before entering sensitive data like passwords, banking details, or OTP information.

The system is built as a two-part architecture:
- Browser Extension: runs in the browser and captures the active tab URL.
- Backend API: receives the URL, analyzes it using rule-based logic and risk scoring, and returns a security verdict.

The goal is to provide a lightweight, intelligent, low-cost security assistant that works without depending on paid external AI services.

2. Problem Statement
--------------------
Phishing attacks and spoofed websites are a major cybersecurity issue. Attackers create fake websites that imitate original brands and trick users into sharing personal or financial information. Many users cannot easily detect these websites, especially when the website uses lookalike domains, typos, suspicious keywords, hidden scripts, or insecure protocols.

GuardianAI addresses this by checking suspicious URL features, page signals, and browser context to classify sites as low, medium, high, or critical risk.

3. Objectives of the Project
---------------------------
- Detect suspicious URLs before users interact with them.
- Analyze domain anomalies such as phishing keywords, IP addresses, suspicious TLDs, and brand impersonation.
- Highlight unsafe patterns like HTTP usage, multiple '@', long tokens, and encoded paths.
- Provide a user-friendly popup-based security result in the browser.
- Give recommendations and explanations for the detected risk.
- Create an easy-to-understand architecture suitable for final year project demonstration.

4. Project Architecture
-----------------------
The project contains the following major components:

4.1 Browser Extension Layer
- Location: extension/
- Main Files:
  - manifest.json
  - background.js
  - popup.js
  - popup.html
  - popup.css

Purpose:
- The browser extension is the user-facing part of the system.
- It detects the active browser tab and reads its URL.
- It sends the URL to the local backend API for analysis.
- It displays the risk score, severity, and summary to the user.

Working:
1. User opens a website in the browser.
2. The extension detects the current tab.
3. It sends a POST request to http://localhost:5000/analyze.
4. The backend performs risk analysis and responds with a score and explanation.
5. The popup displays the result in a readable format.

4.2 Backend API Layer
- Location: Backend/
- Main Files:
  - server.js
  - analyzer.js
  - risk-engine.js
  - ai-service.js

Purpose:
- Acts as the processing engine.
- Receives URL data from the browser extension.
- Runs security checks on the URL and affiliated page signals.
- Computes a risk score and generates recommendations.

4.3 Data and Knowledge Base Layer
- Location: data/
- Main File:
  - knowledgeBase.js

Purpose:
- Stores rules, reasons, mitigations, and recommended actions associated with each indicator.
- This acts like a local knowledge base or rule base for real-time security explanation.
- It helps convert raw detection results into human-readable reasoning.

5. Detailed Components
---------------------
5.1 manifest.json
This file configures the Chrome browser extension. It declares:
- name of extension: GuardianAI
- version
- permissions: activeTab, tabs
- localhost host permission to call the backend
- popup page and background service worker

5.2 background.js
This is the service worker for the extension. It starts when the extension loads and logs a message to confirm activation. It is mainly used to keep the extension alive and support background-friendly browser logic.

5.3 popup.js
This script runs when the popup is opened.
It performs the following tasks:
- Reads currently active tab URL
- Sends it to the backend API as JSON
- Receives the analysis result
- Displays the security severity and risk score
- Shows an explanation generated by the backend

Flow:
- chrome.tabs.query(...) selects the active tab.
- fetch("http://localhost:5000/analyze", {...}) sends the URL.
- response JSON is parsed.
- status-box is updated with the severity and explanation.

5.4 server.js
This is the main Express server.
It provides the API endpoints:
- GET / : health check endpoint to confirm the service is running
- POST /analyze : analyzes a submitted URL in real time
- GET /history : returns the recent scanned URLs and results

It also logs request methods, routes, status codes, and request timing.

It uses:
- express for REST API creation
- cors for browser-to-localhost communication
- JSON parsing for incoming payloads

5.5 analyzer.js
This file performs URL analysis and identifies risky indicators.
It checks:
- dangerous schemes such as javascript:, data:, vbscript:
- raw IP addresses in the hostname
- punycode or unicode obfuscation
- unusual port numbers
- insecure HTTP instead of HTTPS
- suspicious TLDs like .xyz, .top, .zip, .tk
- phishing words such as login, verify, secure, update, account
- brand impersonation patterns
- multiple '@' signs in the URL
- encoded or hidden path data
- suspicious page signals like password fields, insecure forms, and hidden iframes

When a signal is found, it is stored as an indicator object with:
- code
- title
- detail
- severity
- weight

5.6 risk-engine.js
This file calculates the total risk score.
It uses the indicator weights and severity multipliers to compute a numeric score between 0 and 100.

Example logic:
- Each indicator has a weight.
- Severity of the indicator multiplies the score.
- Total weighted value is compared against the maximum possible score.
- The final score is mapped into LOW, MEDIUM, HIGH, or CRITICAL.

It also generates recommendations such as:
- Do not enter sensitive data
- Go to official domain directly
- Enable HTTPS
- Never reuse password

5.7 ai-service.js
This file acts as the explanation generator.
It does not call a real external AI API; instead, it uses a local knowledge base and rule mapping.

It:
- maps each indicator code to a knowledgeBase entry
- generates summary text
- creates human-readable reasoning steps
- builds a final explanation to show in the browser popup

This is a lightweight local AI or rule-based reasoning layer.

5.8 knowledgeBase.js
This file stores rule information for each indicator.
Example entries:
- IP_ADDRESS → suspicious because raw IP addresses are often used by malicious sites.
- PHISHING_KEYWORD → warns about login/verify account-related keywords.
- SUSPICIOUS_TLD → identifies fake or abused domain endings.
- SAFE → marks clean URLs.

These entries contain:
- rule ID
- category
- severity
- summary
- mitigation
- recommendedAction

6. Risk Analysis Logic
----------------------
The core detection system works in the following order:

1. URL is received from the browser.
2. The backend validates whether the URL is valid.
3. The analyzer inspects the URL structure for suspicious patterns.
4. Additional page signals are checked if available.
5. Each suspicious signal becomes an indicator.
6. Risk engine sums indicator weights and produces a score.
7. AI service converts the data into a readable explanation.
8. Final result is sent back to the extension.
9. Popup displays severity, score, and security summary.

7. Example of Workflow
----------------------
Example:
- User visits: http://fake-paypal-login.xyz/account
- Extension reads the tab URL.
- Backend checks: HTTP instead of HTTPS, suspicious TLD, phishing keywords, brand impersonation.
- Risk engine calculates high or critical score.
- AI service generates output like:
  "High risk: several phishing and security signals were detected."
- Popup shows a warning to the user before login.
